0. CONTEXT — WHAT REVIEWSCOPE IS
--------------------------------------------------------------------------------
ReviewScope is an academic Big Data analytics dashboard built on the Yelp Open
Dataset, served from a LOCAL MongoDB. It is a Next.js (App Router) + React +
TypeScript (strict) app, styled with Tailwind CSS and shadcn-style components
(built on Radix UI), icons from lucide-react, charts via Recharts, validation
via Zod, and the official MongoDB Node.js driver.

Two features already exist and MUST keep working untouched:
  - "Overview"           -> route "/"            (components/dashboard/*)
  - "Business Explorer"  -> route "/businesses"  (components/businesses/*)

MongoDB runs locally:
  URI:      mongodb://127.0.0.1:27017   (in .env.local as MONGODB_URI)
  Database: yelp_analytics              (in .env.local as MONGODB_DB)

Collections (confirmed real counts):
  businesses  150,346   <-- your primary collection
  reviews     6,990,280
  users       1,987,897
  tips          908,915
  checkins      131,930

Business document (confirmed real schema):
  {
    business_id, name, address, city, state, postal_code,
    latitude, longitude,
    stars,            // number 1..5 in half steps (business avg rating)
    review_count,     // number
    is_open,          // 1 (open) or 0 (closed)
    categories,       // COMMA-SEPARATED STRING e.g. "Coffee & Tea, Food, Restaurants"
    attributes,       // nested object with "stringy" values
    hours             // nested object: weekday -> "6:0-21:0"
  }
Review document: { review_id, user_id, business_id, stars, useful, funny, cool, text, date }
Tip document (approx): { user_id, business_id, text, date, compliment_count }
IMPORTANT: `categories` is a STRING, not an array. You must $split / $trim /
$unwind to work with individual categories (see lib/dashboard/queries.ts for the

Build these analytics (ALL computed server-side via aggregation; return only
small summarized arrays). Pick strong, clearly-labeled visuals (Recharts via
components/ui/chart.tsx) and tables:

A. CATEGORY MARKET LANDSCAPE
   - For the top ~12 categories (split/trim/unwind the categories string, group,

B. GEOGRAPHIC BREAKDOWN  (by STATE, then drill to city)

C. CATEGORY x GEOGRAPHY CROSS-ANALYSIS  (the standout "variety" piece)

     Let the user choose a category (reuse a Select populated from a bounded

4. HANDLING THE `categories` STRING  (the core "variety" requirement)
--------------------------------------------------------------------------------
Reuse the exact pattern already in lib/dashboard/queries.ts:
  { $match: { categories: { $type: "string", $ne: "" } } },
  { $project: { cats: { $map: {
      input: { $split: ["$categories", ","] }, as: "c",
      in: { $trim: { input: "$$c" } } } } } },
  { $unwind: "$cats" },
  { $match: { cats: { $ne: "" } } },
  { $group: { _id: "$cats", ... } },
  { $sort: { ... } },
  { $limit: N }
Trim whitespace consistently. Match WHOLE categories, not accidental substrings.
Do NOT treat the raw comma-joined string as a single category.

5. PERFORMANCE RULES  (graded on this)
--------------------------------------------------------------------------------
  - All grouping/averaging in MongoDB via aggregation. Return small arrays only.
  - $match early, $limit always. Never find({}).toArray() on a whole collection.
  - Prefer businesses.review_count over scanning the 7M reviews collection.
  - If you ever $lookup across collections, restrict to a SMALL filtered set.
  - Run independent queries concurrently with Promise.all.
  - Do NOT create duplicate indexes blindly or drop existing ones. If an index is
    clearly justified, create it idempotently in a script and DOCUMENT why.
